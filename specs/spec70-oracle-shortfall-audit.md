# Spec 70 — oracle-shortfall zero-case audit

This audit re-reads the re-recorded `bench/baselines/oracle-shortfalls.json` and
answers, per fact-kind per corpus, the question the earlier attribution settled
too early: **is a zero (or near-zero) `actual` a genuine absence, or a producer
that went silent?** The earlier `spec70-oracle-shortfall-attribution.md` attributed
`ddl-declarations → 0` to "C1 null dialect honest cannot-fire". That disposition
accepted a silent producer as expected — the defect this audit corrects.

Governing rule (unchanged): a moved number is attributed to the change that moved
it, or it is an open defect — never a bare re-record.

> **Correction (5-point directive #4) — the fallback below is struck.** An earlier
> revision of this file "fixed" the `ddl-declarations` zero by re-introducing a
> `dialect ?? DEFAULT_SQL_DIALECT` (sqlite) fallback in the four DDL extractors.
> That is the sqlite guess the release bar forbids: a null/ambiguous dialect
> parses under a dialect nothing suggested, producing wrong answers. The correct
> state is **null-dialect abstention** — a null dialect emits zero ops and the
> caller surfaces a `dialect undetermined` cannot-fire reason naming the candidate
> dialects. Do not re-introduce the fallback.

## The correct state (null-dialect abstention, not a fallback)

`src/analyzers/universal/schema/migrations.ts` — the four DDL extractors
(`parseMigrationOps`, the shared `extractDdlColumns` skeleton,
`extractDdlForeignKeys`, `extractMigrationOpsFromFile`) return empty on a null
dialect. A null dialect does **not** skip to a guessed `DEFAULT_SQL_DIALECT`; it
abstains, and the caller surfaces the `dialect undetermined` cannot-fire reason
naming the candidate dialects.

A named dialect still parses. recall-protocol is the only corpus with a detected
dialect (sqlite, via its wrangler D1 binding), and it carries the sole real
residual: 12 op-producing statements across 6 files that node-sql-parser rejects
(valid sqlite the grammar cannot parse — the openstatus `text(N)` class of defect).

## Honest residual that remains

**hhra-org `ddl-declarations` is zero** for a *different* reason than the gate:
its drizzle migrations are postgres dialect
(`bigint PRIMARY KEY GENERATED BY DEFAULT AS IDENTITY (sequence name …)`), and
`node-sql-parser` does not parse that `GENERATED … AS IDENTITY` spelling under any
dialect — including an explicit `postgresql` (probed: `ops = []`). hhra-org is
also *ambiguous* (`pg` **and** `mysql2`), so `detectDialect` correctly names no
dialect and the producer abstains rather than guessing. This is a
**parser-limitation + ambiguity** residual, not a gate; the honest outcome is zero
ops with a named reason, not a parse under a guessed dialect.

## Disposition

- `ddl-declarations` — null-dialect abstention is the correct state; the `0` on
  hhra-org/blitz/openstatus is honest cannot-fire, not a silent producer. No
  fallback.
- `dynamic-sql`, `schema-usage:blitz`, `security-candidates:hhra-org`,
  `batch-functions:blitz` — **correct absence**, no code change; the composition
  notes already describe the residual correctly.
- `loop-queries:blitz/openstatus` — **attributed strictness**, not a gate; a
  coverage-gap follow-up (prove ORM receivers via R4) is out of scope for this
  release and tracked separately, not re-recorded here.

Baseline re-record is deferred to the end of the release (after the double-parse
collapse) so the snapshot is taken once over the final producer behavior.
